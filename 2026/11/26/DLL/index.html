DLL

发表于2026-11-26|更新于2026-11-27|笔记
|浏览量:

DLL，动态链接库，他包含了很多共用的代码和数据等等，可供其他模块使用
而DLL里并不是所有的函数都必须供其他模块使用，而是只有经过导出的函数才能被其他模块使用。

DLL的意义就是，如果一份代码简单的附加到调用的程序里，就是两份代码。而使用DLL文件，物理内存中只有一份代码，不过是被分别映射到了不同的进程内存空间，从而极大地降低了内存消耗。

DllMain

入口函数：DllMain函数是DLL模块的默认入口点

main 或 WinMain 对于可执行文件（EXE）通常是必需的。但是DllMain对于DLL并不是必须的。
Windows 加载器并不直接调用你写的 DllMain。对于一个标准的 C/C++ DLL，链接器设置的默认入口点是 C 运行时库（CRT）提供的一个函数：_DllMainCRTStartup

它的工作是先完成 CRT 自身的初始化（比如全局变量、线程局部存储等），然后它才会尝试去调用名为 DllMain 的用户函数（如果存在的话）。

而如果你不提供DllMain的话，链接器会默认给你提供一个DllMain。

而DllMain的意义是什么呢？当你的 DLL 需要在加载/卸载或线程创建/销毁时，执行自定义的初始化或清理工作时，就需要它
DllMain 会收到一个 fdwReason 参数，用来区分不同的调用时机：

DLL_PROCESS_ATTACH：DLL 被加载到进程时。

DLL_PROCESS_DETACH：DLL 从进程卸载时。

DLL_THREAD_ATTACH：进程创建新线程时。

DLL_THREAD_DETACH：线程终止时。

如果这些时机你都不需要做任何特殊处理，那么省略 DllMain 是完全安全的。

APIENTRY：这是一个宏定义，代表 __stdcall
hModule:当前DLL的句柄
ul_reason_for_call:调用原因
lpReserved：保留参数

DLL_PROCESS_ATTACH:进程附加,有一个新的程序（进程）把这个 DLL 加载到了它的内存里。
DLL_THREAD_ATTACH:线程附加,加载了这个 DLL 的程序里，新建了一个线程。
DLL_THREAD_DETACH:线程分离,程序里的某个线程结束了。
DLL_PROCESS_DETACH:进程分离,程序要把这个 DLL 卸载掉，或者程序本身退出了。

导出

我们之前提到：DLL里并不是所有的函数都必须供其他模块使用，而是只有经过导出的函数才能被其他模块使用。

而导出DLL的方式：

  1. 声明导出

    pch是 Pre-Compiled Header（预编译头文件） 的缩写
    是 Visual Studio（VS）自动生成的，你可以把那些常用且几乎不会去修改的头文件，统统塞进 pch.h 里。

    extern “C”：我们都知道c++有重载机制，名称可以一样，只要参数不同即可，为什么呢？就是因为c++有名称粉碎机制，但是名称粉碎的话，我们就没办法以名称导出了，所以我们选择使用extern “C”，告诉编译器用纯c的命名规则来编译，不改变他的名字。

    __declspec(dllexport)：__declspec 是微软特有的修饰符，dllexport就是dll导出。它告诉编译器把这个函数的名字和地址，写进 DLL 的导出表。

    function：函数声明，类似于extern “C” __declspec(dllexport) int Add(int a, int b);这种。

  2. 模块定义文件导出

    我们创建一个.def文件

    LIBRARY “MyDll”:链接器会在生成的 .dll 文件头（PE 头）里写上MyDll这个名字。
    EXPORTS:导出的开始,告诉链接器下面列出的一行行名字，都是允许外部程序调用的函数或变量,可以加进导出表。

    my_main @ 1：my_main只是一个示例，你在这里标注出你要导出的函数名，@ 1是该函数指定的序号

    模块导出文件的意义：
    不改源码强行导出：可以在不改变.h或者.c的情况下，强行导出
    控制导出名：有时候代码里的函数叫 InternalName，但你希望外部调用时叫 PublicName，.def 文件可以轻松实现：PublicName = InternalName

DLL导入

  1. 通过隐式链接的方式调dll导出的函数(需要.lib)

    #pragma comment(lib,”xx.lib”)
    作用就是让链接器在创建exe的同时把.lib接上，你的 EXE 程序在刚启动的时候，操作系统就会自动帮你把需要的 DLL 找出来并加载进去。如果找不到，程序直接启动失败
    #pragma 的作用是给编译器下达“特定指令”
    comment作用是给链接器（Linker） 传递一个附加说明
    lib：告诉链接器：“接下来的这个参数，是一个 .lib 格式的库文件”

    对于dll项目，编译器会产生两个文件，分别是.DLL和.lib其中dll是动态链接库，lib是导入库，保存了一些符号和地址的对应地址和信息，不能单独使用，必须与dll共存，用于动态链接库的隐式链接。

    .lib里面存放了这些信息：
    DLL文件名
    符号表：记录了 DLL 里到底导出了哪些函数名比如 my_main、Add
    桩代码：对于每一个导出的函数，导入库会生成一段极短的跳转代码。比如你代码里调用了 Add(1, 2)，链接器不会把真实的加法代码放进来，而是把这个“桩代码”放进来。

    不过要注意，无论是通过#include “MyDll.h”还是在exe的头文件里标注，都要提供函数声明。

  2. 显示链接方式调用导出函数(不需要.lib)

    这个方法要用到Windows的api函数LoadLibrary()

    typedef int (*PFN_MY_MAIN)(int, int); // 定义函数指针类型

静态库

静态库又叫对象库，其中的代码在运行链接器进行静态链接时被添加到程序的exe文件中，静态链接库最终会与调用程序融为一体，其文件后缀也是.lib

静态链接库只能隐式调用。
