the-usage-of-git

📦 场景一：从零开始（一次性配置）
指令 作用
git init 把当前文件夹变成 Git 仓库（生成隐藏的 .git）
git config –global user.name “名字” 设置提交时的署名 第一次用 Git 必须设置
git config –global user.email “邮箱” 设置提交时的邮箱 第一次用 Git 必须设置
git remote add origin 关联远程仓库（告诉 Git 推送到哪） 连 GitHub 时用，只需一次
📝 场景二：日常存档（核心三步曲）
指令 作用
git status 查看当前状态（哪些文件改了/没提交） 没事就敲一下，看自己写到哪了
git add . 把当前所有修改放入“暂存区”（准备提交） 写完文章，敲这个打包
git commit -m “说明” 正式存档，生成一个历史版本 敲完 add 后，敲这个存档
☁️ 场景三：云端同步
指令 作用
git push origin main 把本地存档推送到 GitHub 的 main 分支 敲完 commit 后，传云端备份
git pull origin main 把 GitHub 上的代码下载并合并到本地 换电脑写作时，或者报错了先拉取
git push -f origin main 强制覆盖远程分支（慎用！）
🌿 场景四：时间旅行与分支
指令 作用
git log –oneline 查看所有存档记录（每行一个版本） 想看看自己过去写了啥
git restore <文件> 还没 commit，但改坏了，撤销修改 文章改乱了，想恢复到上一次存档的状态
git branch -M main 把本地默认分支改名为 main
git checkout <分支名> 切换到另一个平行世界（分支） 比如切到 gh-pages 看网页成品
git tag -a v1.0 -m “发布” 给当前版本打一个标签
🌍 场景五：查漏补缺
指令 作用
git diff 查看具体改了哪几行代码 忘了刚才改了啥，看这个
git remote -v 查看当前仓库连的哪个 GitHub 地址 确认有没有连错仓库
git reset –hard HEAD~1 危险！ 撤销上一次 commit 并丢掉改动 刚提交了垃圾文件，想反悔
