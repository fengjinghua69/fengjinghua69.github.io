虚函数与动态联编

用Virtual修饰的函数是虚函数。
Virtual修饰的函数属于动态联编
不加virtual修饰的函数属于静态联编。
虚函数就是为了实现多态而诞生的。

在继承中父类的指针能指向子类对象，但是子类指针不能指向父类对象。

重写机制：在c++中子类定义了一个与父类名字相同，类型相同，参数相同，返回值相同的函数。并且父类的那个函数前面带有virtual关键字，哪子类就使用子类提供的函数实现，这个就叫重写。

无Virtual：

有virtual：

没用虚函数的情况呢，两者使用的都是父类，而使用了虚函数的情况呢，指向子类的，就会使用子类的函数。
这就是静态联编和动态联编的区别
前者因为没用虚函数，属于静态联编，你定义了一个父类类型的指针那编译器就直接把 CPerson::say 的地址写死到生成的汇编代码里。
而后者就属于动态联编，而动态联编呢，就涉及虚函数表了编译器在编译时不知道你到底要调哪个函数，于是使用指令，在程序运行的时候，顺着vptr去找虚函数表，表里的是那个地址，就调用那个，于是，多态的效果实现了。

顺着虚表指针，我们能再找到这样的地址，转到反汇编看看

32的版本呢，就是会现这样的增量链接。为了加快编译速度，编译器不会把虚函数表直接指向真实代码，而是指向一个专门存放 jmp 指令的“中转站”。

子类2.0（多继承）

这次给子类整一对浮木，他现在是个多继承

会有所不同吗？

我们发现大小并不是刚刚的8，而变成了16，多了一倍，多了一个虚表指针，一个一个来看

经过调试查看发现，两个虚表指针，第一个表里，存放着指向父亲的指针和指向儿子的指针。第二个表里存放着指向母亲的指针。为什么是这样呢？

原因在于在多继承的情况下
虚函数表分为主表副表
主虚表永远在第一个有虚函数的父类那里，不管你有几个父类，编译器都会把第一个有虚函数的父类的虚表当成“主表”。子类新增的虚函数，统统追加在这个主表的最后面。
多出来的父类，配发专属“副表”。除了第一个父类，后面的父类只要含有虚函数，就会给对象增加一个 vptr，指向它们自己的“副表”。
假设此时 son 重写了母亲的函数
class son : public father, public mother {
public:
virtual void say() {} // 重写父亲
virtual void singing() {}// 重写母亲
virtual void walk() {} // 新增
};
主虚表（父亲区）：say 的格子会被替换成 son::say。walk 追加在后面。
副虚表（母亲区）：singing 的格子会被替换成 son::singing。
