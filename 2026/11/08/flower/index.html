花指令（Junk Code）实战笔记

适用于：x86/x64 上”跳转 + 垃圾字节”型花指令（CTF 入门级 90% 都是这种）

  1. 一句话本质
    代码块
    花指令 = 一个跳转 + 它跳过的 N 个随机字节
    它的目的不是骗 CPU，是骗反汇编器（IDA / Ghidra / objdump）。
  1. 为什么它能骗到 IDA
    CPU（真正运行程序时） IDA（静态分析时）
    怎么工作 真的执行指令 从段开头逐字节线性解码
    遇到 jz 真的跳过去 不跳！照样往下解码
    会碰到垃圾字节吗 不会（被跳过了） 会！一路解码下去
    垃圾字节有害吗 没影响 有害！把指令边界搞乱
    出问题的机制
    代码块
    字节流： 74 03 | 44 | 55 | 66 90 | 33 C0
    jz inc push xchg xor …

IDA 这样读：
0x40110E 74 03 jz …
0x401110 44 inc esp
0x401111 55 push ebp
0x401112 66 90 xchg ax,ax ← 占 2 字节：0x401112 + 0x401113
0x401114 33 C0 xor eax,eax

CPU 这样走：
0x40110E 74 03 jz 0x401113 → 直接跳过 0x401110~0x401112
结果：0x401113 这个字节，同时属于两条不同的指令。 → 控制流图自相矛盾 → Hex-Rays 建不出微码 → F5 失败
IDA 显示 loc_401112+1，含义是：「跳转目标是 0x401112 这个地址 + 1 字节」， 也就是”落在了 0x401112 这条指令的里面”。

  1. 识别：四个特征

特征 可靠度

① 跳转目标带 +1 / +2 / +3（如 loc_401112+1） ⭐⭐⭐ 铁证，零误报。正常编译器永远不会跳到指令中间
② xor r,r / test r,r / cmp r,r 后面跟 jz 或 jnz ⭐⭐⭐ 同一寄存器自己异或自己 = 0，条件恒真或恒假，说明它只是想”无条件跳过字节”
③ jz 和 jnz 指向同一个地址 ⭐⭐ 双跳夹击，一真一假，结论都是跳过中间
④ 反汇编出现”怪指令”：inc esp、重复的 push ebp、xchg ax,ax（2字节nop）、adc dh,[…]…… ⭐ 只作为线索，不能只凭这个判断！
⚠️ 特征 ④ 最不靠谱。垃圾字节是随机生成的，解码成什么纯属巧合。 出题人自己都不知道它会解码成什么。别靠”看起来怪不怪”来判断。

  1. 核心判别规则（唯一一条，必须记住）
    看到一条可疑指令，不要问”它像不像垃圾”，只问一个问题：
    代码块
    ┌─────────────────────────────────────────────┐
    │ 它落在「跳转的下一条指令」到「跳转目标」之间吗？ │
    └─────────────────────────────────────────────┘
    │
    是 ─────┴───── 否
    ↓ ↓
    → 垃圾 → 真代码
    → 改成 90 → 绝对别动
    花指令的识别是「算术」，不是「眼力」。你只要会做减法，就一定能找出来。
  1. 处理：五步流程
    代码块
    ① 找 xor r,r / test r,r 后面的条件跳转（可疑点）
    ↓

② 看跳转目标地址（IDA 注释里的 loc_xxxxxx）
↓
③ 垃圾长度 = 跳转目标 − 跳转的下一条指令
↓
④ 从”跳转下一条”开始，数③那么多字节，全部改成 90
↓
⑤ 那个 +1 会自动消失；F5 就能用了
第 ⑤ 步为什么会自动消失？
因为 90 是 1 字节指令，改完之后每个地址各自成为一条独立指令：
代码块
改之后：
0x401110 90 nop ← 1 字节
0x401111 90 nop ← 1 字节
0x401112 90 nop ← 1 字节
0x401113 90 nop ← 现在它是一条独立指令的开头！
0x401114 33 C0 xor eax,eax
跳转目标 0x401113 从”指令中间”变成了”指令开头” → 重叠消失 → 控制流图干净。

  1. IDA 操作速查
    操作 快捷键 / 菜单
    跳到地址 G
    选中一段 点第一行 → 按住 Shift → 点最后一行
    改字节 Edit → Patch program → Change byte…

改汇编（不用算字节） Edit → Patch program → Assemble… → 输入 nop
查看交叉引用 X
取消定义 / 重新定义代码 U / C
反编译 F5
写回文件（想让程序能跑） Edit → Patch program → Apply patches to input file
推荐做法
• 一次选一整段，用 Change byte 把 44 55 66 直接改成 90 90 90，比逐条 Assemble 快
• 改完按 F5 不行的话，在花点处按 U 再按 C，强制 IDA 重新解码

  1. 验收标准（怎么知道改对了）
    检查项 改对的表现

① IDA 标签 loc_401112+1 → 变成 loc_401113（+1 消失）
② 按 F5 能弹出伪代码窗口
③ 运行程序 行为完全不变

  1. 坑 / 易错点
    ⚠️ 坑 1：不能”删”字节，只能”覆盖”
    二进制里不能删除字节 —— 一删，后面所有地址前移，跳转全乱，程序直接废。 做法是原地改写成 90，长度不变。
    ⚠️ 坑 2：千万不要只删跳转、留着垃圾
    如果只把 jz 改成 nop 而不动垃圾：
    代码块
    0x40110C xor eax,eax
    0x40110E 90 nop ← 跳转没了
    0x401110 44 inc esp ← CPU 直接执行进来了！栈被破坏
    0x401111 55 push ebp
    跳转是好人（它保护 CPU 不走垃圾），垃圾是坏人（它骗 IDA）。 → 留跳转，改垃圾。
    ⚠️ 坑 3：xchg ax,ax 是 2 个字节
    66 90 占两个地址。跳转目标落在它第二个字节上时，你只需要改第一个字节 66 → 90， 第二个字节本来就是 90。
    ⚠️ 坑 4：同样形状的指令，有真有假
    push ebp 在函数开头是真代码（栈帧），在垃圾区间里是垃圾。 唯一判别标准就是”在不在跳转的跳过区间里”。
    ⚠️ 坑 5：patch 只改 IDA 数据库
    在 IDA 里 patch 不会动原 exe。想让 F5 生效，改数据库就够了； 只有想让改完的程序能运行，才需要 Apply patches to input file。
    ⚠️ 坑 6：F5「完全没反应」≠ 花指令
    • F5 弹报错（Cannot convert to microcode 等）→ 才可能是花指令
    • F5 完全没反应（不弹窗、不切换窗口）→ 是光标不在函数里 / 没有反编译器 / 焦点不对
    这时要查：右键菜单里有没有 Decompile？点一下有没有反应？ 老版 IDA Free（7.x）对 32 位 x86 就没有反编译器。
  1. 速查口诀
    代码块
    花 指 令 = 跳 转 + 它 跳 过 的 字 节

不看内容，只量距离
垃圾长度 = 目标地址 − 跳转下一条地址

区间之内 → 改 90
区间之外 → 别乱动

跳转留着，垃圾改掉
什么时候不是这种花指令
类型 特征 应对
跳转+垃圾（本笔记） 上面讲的 改 90
控制流平坦化（OLLVM） 一个大 switch + 状态变量，函数被切成块 手动 patch 很难，用去平坦化脚本 / Angr / miasm
VM 保护 有解释器循环 + 字节码数组 基本要写模拟器
加壳 入口代码很乱，有解密循环 先脱壳
