the Usage Cheat Engine

发表于2026-11-08|更新于2026-11-08|笔记
|浏览量:

我是看b站上的植物大战僵尸修改，了解了一下CE的基本用法，实际上CE是很强大的工具，我要了解的还很多TvT

我会加油的
这里只是丰富一下我的博客…如果真的想快速了解，去b站找一下简单的教程，了解到前几集就可以知道它的基本用法愉快的修改一些本地的小游戏的数值玩一下啦

看谁“保存/记录”了阳光对象基址（esi）的值，然后一层一层往上找，直到找到“最初的记录者”——也就是位于模块（.exe）里的静态基址。
这里的“调用”我们可以理解为“引用”或“存放”。因为模块基址并不是直接“调用”阳光，而是模块基址 + 偏移A 这个地址里，存放着指向下一级的指针。
我们把你在CE里实操的过程，用你现在的理解串一遍：
1. 起点（动态）：你找到了阳光数量，地址是 0x1A2B92C8。这个地址每次重启都会变，没用。
2. 第一步溯源（找esi）：你查看“什么访问了这个地址”，发现指令是 mov eax, [esi+5560]。此时 esi 的值是 0x1A2B3D68。你明白了，0x1A2B3D68 就是阳光对象基址。
3. 第二步溯源（找指针）：你拿着 0x1A2B3D68 去CE里搜索（搜数值），搜出来一个地址，比如 0x0A0B0C00，这个地址里的值刚好是 0x1A2B3D68。这就意味着：0x0A0B0C00 是存放阳光对象基址的“抽屉”。
4. 继续溯源（找基址）：你再去查“什么访问了 0x0A0B0C00”，发现是 mov ecx, [eax+768]，此时 eax 的值是 0x0A0B0000。你再搜 0x0A0B0000……
5. 终点（静态）：你一直往上找，最后一步搜出来的地址变成了绿色的 “PlantsVsZombies.exe” + 0x2A9F0。你查看它的值，发现它指向了上一级的指针。
此时你终于得到了一条完整的寻宝路线（指针链）：
[[[PlantsVsZombies.exe + 0x2A9F0] + 0x768] + 0x0] + 0x5560
• PlantsVsZombies.exe + 0x2A9F0 在CE里永远是绿色的，因为游戏每次启动，不管它加载到哪里，CE都知道去 .exe 的起始位置加上 0x2A9F0 去找那个初始抽屉。
• 只要拿到了这个公式，哪怕阳光对象（esi）藏到天涯海角，操作系统每次给它分配什么新地址，你都能顺藤摸瓜，精准算出当前的阳光数量！
这就是为什么我们要找基址：
一旦写出了 [[[PlantsVsZombies.exe + 0x2A9F0] + 0x768] + 0x0] + 0x5560 这个公式，你就可以把它写进修改器里。无论你怎么重启游戏，修改器每次运行这个公式，都能稳稳地找到阳光，实现“锁定阳光”或者“无限阳光”。
