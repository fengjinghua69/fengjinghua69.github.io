PE-export

发表于2026-11-17|更新于2026-11-23|笔记PE结构
|浏览量:

之前在可选PE头中，有两个个字段：NumberOfRvaAndSize、DataDirectories。

前者表示了数字目录表的个数，而后者是一个数组，其中每个元素存着数字目录表的偏移的大小。

RVA:内存中的偏移。FOA:文件中的偏移。

我们利用其中的VirtualAddress来定位，这就是数据目录表的RVA，用它，转化为FOA，用FOA+Filebuffer来寻找数据目录表，而数据目录表在数据段。
所以寻找数据目录表的整体思路就是可选PE头->NumberOfRvaAndSize、DataDirectories->数据目录表偏移->数据段的数据目录表。

而怎么转化RVA和FOV呢？我们就要利用到区段表中的VirtualAddress和PointerToRawData，他们是区段的RVA和FOA。
RVA-区段的RVA=表距离区段开头的距离
FOA-区段的FOA=表距离区段开头的距离
∴FOA=RVA-区段的RVA+区段的FOA
RVA=FOA-区段的FOA+区段的RVA
用这个方法，我们就可以找到导出表。

NAME

DLL 自身的名称字符串的 RVA,并不是直接写的名字字符串，而是指向导出表文件名的偏移，属于RVA，同样属于需要我们取手动转化为FOA的，FOA+FileBuff，得到char* name

Base

导出函数的起始序号，序号等于表的序号+Base，详见AddressOfNameOrdinals

NumberOfFunction

导出函数的数量，并不一定是准确的数量，而大致是序号的最大值-最小值+1得出的结果，但其实这样说并不准确
不是说 PE 解析器通过最大序号和最小序号计算 NumberOfFunctions，而是 EAT 本身有 6 个位置，Base 决定了第一个位置对应的序号。
另外，EAT 中可能存在值为 0 的空项，所以不能保证每个位置都对应一个有效函数。

这个案例很清楚的展示了以上的问题，这里的NumberOfFunction并不是3而是7-2+1=6。

NumberOfName

以名称导出的函数个数

接下来的三个表才是重中之重！导出表不是简单地把函数名称和函数地址排列在一起，而是由三个相互关联的数组组成。

导出表的核心组成

  1. EAT — Export Address Table

导出地址表：存储导出函数的 RVA。

  1. ENPT — Export Name Pointer Table

导出名称指针表：存储函数名称字符串的 RVA。

  1. EOT — Export Ordinal Table

导出序号表：存储名称指针表中每个名称对应的 EAT 下标。

AddressOfFunction

EAT 导出函数地址表，RVA，需要转成FOA。
EAT 里面存储的是一系列 DWORD，每个 DWORD 对应一个函数的 RVA。

AddressOfNames

ENPT 导出函数名称表，同上。
ENPT 它存储的是一系列 DWORD，每个 DWORD 都是一个函数名称字符串的 RVA。
ENPT 存储的不是函数名称本身，而是函数名称字符串的 RVA！
所以需要再进行一次寻址：
char* name = (char*)(base + nameRVA);
这里的 base 是 DLL 的实际加载基址。

AddressOfNameOrdinals

EOT 导出函数序号表，同上。
EOT EOT 中的每个元素是一个 WORD，也就是 2 字节。记录ENPT 中某个函数名称对应 EAT 中的哪个下标。
而刚刚我们提到Base，我们看到的序号就是这个表的序号加上Base得到的结果。

接下来是最最重要的，我们应该如何运用这三个表呢？看下图！

我们找函数，通过两种方式:

  1. 名称查找

当我们通过名称查找时，就运用到ENPT，也就是AddressOfNames指向的表，例如，我们去里面找到了name6，我们就看它是第几个元素，也就是前面的“元素序号”，
它对应的是5，拿着这个序号去找EOT，也就是AddressOfNameOrdinals指向的表，你按照刚刚的“元素序号”5，找到它里面存的序号，也就是5对于应里面存的是谁，
这里对应的是6，那么我们拿着这个真正的序号取找EAT，也就是AddressOfFunction指向的表，把刚刚拿到的真正的序号当作“元素序号”去找，就能找到对应函数的偏移。

  1. 序号查找

当我们通过序号查找的时候，把序号减去Base，得到Ordinal，再去EAT里找偏移。
